# 「签变时光」(qbsg.top) 生态调研 —— 有什么能借鉴

调研日期 2026-09-28。站点是一个**电子价签固件/文档/上位机**的社区分发平台，
面向的正是我们这类 GR5513 / DA14585 墨水屏价签。

## 2. 他们的协议（从网页 JS 里读出来的）

```
广播名    前缀 "NRF-"（网页就是按 namePrefix 筛设备）
服务      13187b10-eba9-a3ba-044e-83d3217d9a38
特征      4b646063-6264-f3a7-8941-e65356ea82fe   写 + 通知
另有      00001f10-… / 00001f1f-… / 0000221f-…   （另一族，optionalServices 里挂着）

命令      两字节起步：[opcode][arg] …
  刷屏    先 '00'+xx 再 '01'
  传图    块 = [03 | plane | offset(2B) | payload]     plane: 00=黑白, ff=红
           总长 7000/18000 的图走 opcode 04（小屏那档）
           偏移按半字节递增（step 也是字符串半长）
```

## 3. 三个决定性结论

1. **我们原厂固件不是这套协议**：出厂备份 512KB 里，`NRF-`、`ZK42V`、
   `62750001-…`（tsl0922 那套）、`13187b10-…`（这套）**一个都没有**。
   跟之前反汇编的结论一致 —— 原厂 APP 压根没建 GATT 服务（走的是 ZKONG 私有那套）。
   ⇒ 现成的社区网页**驱动不了原厂固件**，但**可以驱动我们自己的固件**（只要我们讲这套协议）。
2. **他们的固件是另一套 flash 布局**：`PP5513_ 4.2.bin`(142096 B) 开头
   `SP=0x30020000 / 复位=0x01020059` ⇒ 载入地址 **0x01020000**、栈顶用满 128KB RAM；
   我们 ZK42V 是 app@0x0100A000、栈顶 0x30014000。
   ⇒ **不能直接刷到我们板上**（bootloader 对不上）。
3. **他们的 4.2 屏驱动跟我们那块不是同一套**：文件里有 `Goodix` 字样（同一颗芯片/SDK 系），
   但**没有**我们逆向出来的那段初始化序列（`74 54 7E 3B 2B 04 63 …`）。
   ⇒ 屏驱动/初始化不能照搬；但**农历/黄历的表和算法是硬件无关的**，可以借鉴。

## 4. 建议怎么用（按性价比）

1. **抄功能清单**（最省事、收益最大）：把网页里那些我们还没有的排进 backlog ——
   局刷校准、休眠时段（定时白屏省电+除残影）、倒计时（单次/重复）、旋转 180°、
   反色、字体/字号/偏移、停车牌、闹钟/LED。这些**都不需要改协议**。
2. **农历/黄历**：他们有一整族「黄历版」固件；也可以直接用手边的
   `GUI/Lunar.c`（原厂那份，自包含 C）—— 后者更省事，先做这个。
3. **想要现成的强上位机** ⇒ 我们的固件去讲他们那套协议（服务 `13187b10`、
   特征 `4b646063`、广播名 `NRF-xxxx`）。命令骨架已经挖到（见上），
   再把固件侧的 `03/04` 分块语义逆完整就能对接；好处是两个功能齐全的网页白送。
4. 他们的下载里还有 JLink/串口烧录工具与安装教程 —— 需要时再取。

> ⚠️ 这些是**第三方产品资料**：借鉴思路/协议/表格数据可以，但**别把别人的固件或代码
> 原文搬进我们的仓库**（许可不明）。文档里记录出处即可。

## 5. 版式借鉴（2026-09-28 第二轮：把日历页画好看）

起因：我们的日历页（build 28）农历能算对，但**画面丑** —— 左边红面板塞表盘 + 大数字、
右边硬塞月历，两边都挤，大数字还是 5x7 点阵放大 7 倍。

### 现成的图从哪来

`/api/firmware/catalog` 里**每个固件都带一张实屏截图**（`image_url`，走
`https://qbsg.top/providers/<uuid>/<uuid>.jpg`）。53 个固件里 4.2 寸那 14 个挑出来看：

| 固件 | 版式 | 结论 |
|---|---|---|
| `HM42_AIO_V1.1.1`（4.2 时钟日历，简体） | 整机实拍 | 只能看到外壳，参考价值低 |
| `GR5513新黄历简体文字` | 老黄历：大红数字 + 农历 + 干支 + 宜忌 | 信息太多，我们字模撑不住 |
| `三色纯日历版` | **整页农历月历**：`2025年08月 农历六月初蛇年` + 星期条（六/日红）+ 格子里大日号 + 小农历 + 今天红圈 | **← 就是它** |
| `4.2新界面` | 顶部一行 `2026年05月23日 星期六 戌时 28℃` + 超大 HH:MM | 时钟页可以照这个做 |
| `gr5513三色墨水屏固件` | 上左时钟 + 上右月历的小双栏 | 我们 build 28 那版就是这个路子，太挤 |

### 借了什么（只借版式，代码全是我们自己写的）

build 29 的日历页 = 整页农历月历：

```
┌───────────────────────────────────────────────┐
│ 黑条   2026年09月      农历八月        星期日  │
├───────────────────────────────────────────────┤
│  一   二   三   四   五  [六]  [日]           │  六/日 红底白字
├───────────────────────────────────────────────┤
│    1     2     3     4     5     6     7      │  大日号（5x7 放大 3 倍）
│   廿一  廿二  廿三  廿四  廿五  廿六  廿七     │  小农历（16x16 原大）
│  …（今天那格整块红底白字）…                    │
└───────────────────────────────────────────────┘
```

时钟页则照 `4.2新界面` 的路子：同一个黑条表头 + 大表盘 + 底部黑底白字时间。

### 顺带解决的一件事：字模

社区那些固件的汉字在小尺寸下都清清楚楚，靠的是**真字体**，不是手画。
我们原来那 18 个汉字是手画的矩形（`CJK_RECTS`），简单的字还行，复杂的字完全认不出
（build 28 的日历页上「初」被画成 π、「廿」成一条横线）。
build 29 改成：用系统里的**冬青黑体简体中文**在 15px 下栅格化成 16x16 点阵
（`tools/cjk_from_ttf.py`，需要 Pillow），结果作为 ASCII 点阵存进
`tools/cjk_ascii.py`，再照常生成 `zkgui_font.h`。
字模从 18 个加到 23 个（新增 年/星/期/农/历），**只多占 320 字节 flash**。
