# ZK42V-N 墨水屏逆向结果（2026-09-22）

结论先放前面：**这颗价签的屏是 4.2 寸、400x300、黑白红三色、SSD1680/1683 那一族的
4 线 SPI 墨水屏控制器。** 全部参数在固件里都是硬编码常量，不需要跑起来猜。

## 1. 证据链（怎么一步步锁定的）

1. 器件配置记录在 flash `0x01057000`（备份文件偏移 `0x57000`），固件启动时读它：

   ```
   01057000  43 03 00 00 00 00 00 00 02 FF 07 03 04 05 06 18
   01057010  08 00 00 00 5A 4B 43 34 32 56 2D 4E FF FF FF FF
   ```

   * `[0] = 0x43` = 屏型号码（打印出来就是串口日志里的 `<67 3>` 的 67）
   * `[1] = 0x03` = 面板类型（同上，日志里的 3）
   * `[8..15] = 02 FF 07 03 04 05 06 18` = **屏的 8 根引脚编号**
   * `[16] = 8` = 型号字符串长度
   * `[20..] = "ZKC42V-N"` = 型号

2. `screen_init` 在 `0x010201D8`，它把上面两个字节读进来，
   然后 `switch (cfg[0])` 分发到各屏型专属的驱动加载函数。
   `cfg[0] = 0x43 = 'C'` 落到 `0x0100E764`。

3. `0x0100E764` 里明明白白写着：

   | 字段 | 值 | 含义 |
   |---|---|---|
   | `dev[4]`  (u32) | 30000 | 图像缓冲区字节数 |
   | `dev[8]`  (u16) | 400 | 宽 |
   | `dev[10]` (u16) | 300 | 高 |
   | `dev[0x50]` | 0x0100E748 | 初始化入口 |
   | `dev[0x54]` | 0x0100E75C | 写一帧图像 |
   | `dev[0x58]` | 0x0100FE20 | 刷新显示 |
   | `dev[0x5C]` | 0x0101001A | 休眠 |
   | `dev[0x60]` | 0x01010DC0 | 释放引脚 |

   400 x 300 x 2 个平面 / 8 = 30000 字节，跟 `dev[4]` 完全对上。

## 2. 引脚（`pins[8]`，编码是 `(port << 6) | pin`）

| 索引 | 值 | 解码 | 作用 |
|---|---|---|---|
| pins[0] | 0x02 | P0_2  | **CS**（每个字节拉低再拉高） |
| pins[1] | 0xFF | —     | 未使用 |
| pins[2] | 0x07 | P0_7  | **RST**（复位时拉低 1ms 再拉高） |
| pins[3] | 0x03 | P0_3  | **SCLK** |
| pins[4] | 0x04 | P0_4  | **SDI/MOSI**（读状态时复用成 MISO） |
| pins[5] | 0x05 | P0_5  | **DC**（0=命令，1=数据） |
| pins[6] | 0x06 | P0_6  | **BUSY**（输入） |
> **2026-09-27 更正**：引脚编号这块芯片上是**全局 0~31** 编号，不是 (port<<6)|pin：
> 编号 0~15 = GPIO0 的 bit0~15，编号 16~31 = **GPIO1** 的 bit0~15
> （依据：SDK 的 `drivers/src/app_io.c` 里 `APP_IO_TYPE_NORMAL` 分支就是这么映射的）。
> 所以下面 pins[7] = 0x18 = 24 是 **GPIO1 bit8 = P1_8**，不是 P0_24。
> 我一开始按 P0_24 去 `app_io_init(APP_IO_TYPE_GPIOA, APP_IO_PIN_24)`，
> 被 SDK 直接拒绝（GPIOA 只收 bit0~15），那根脚从来没被驱动过 ——
> 实机表现就是"命令发出去了、屏也刷了 21 秒，但画面不动"。改用
> `APP_IO_TYPE_NORMAL` + `APP_IO_PIN_24`（落到 P1_8）之后才真正驱动到它。

| pins[7] | 0x18 | **P1_8**（原写 P0_24，见上面的更正） | 屏供电/使能一类的辅助脚 |

依据：
* `0x010115D8`（写命令）= CS 低 → SCLK 低 → **DC 低** → 8 位 MSB first 时钟 → CS 高
* `0x01011648`（写数据）= 同上但 **DC 高**
* `0x01011FC8`（复位）= pins[2] 拉低 1ms → 拉高 1ms → 发 `0x12`
* `0x0100D240/0x0100D250`（等 BUSY）= 读 pins[6]，超时 5000 万次
* `0x01011558`（读回一个字节）= pins[4] 切输入，时钟 8 次，MSB first

## 3. 完整初始化序列（`0x01010802`，屏型 'C' 专用）

```
pins_init()                       ; 0x100D1B0 把上面 7 根脚配成输出/输入
reset()                           ; pins[2]=0, delay 1ms, pins[2]=1, delay 1ms
                                  ; CMD 0x12, wait_busy

CMD 0x74, DATA 0x54
CMD 0x7E, DATA 0x3B
CMD 0x2B, DATA 0x04, 0x63
CMD 0x0C, DATA 0x8E, 0x8C, 0x85, 0x3F    ; Booster Soft Start
CMD 0x01, DATA 0x2B, 0x01, 0x00          ; 驱动输出 = 300 行（由高度算出来的）
CMD 0x11, DATA 0x01                      ; 数据进入模式
CMD 0x44, DATA 0x00, 0x31                ; RAM X 起止 = 0..49    (50 字节 = 400 位)
CMD 0x45, DATA 0x2B, 0x01, 0x00, 0x00    ; RAM Y 起止 = 299..0
CMD 0x3C, DATA 0x01                      ; 边框波形
CMD 0x18, DATA 0x80                      ; 内部温度传感器
CMD 0x22, DATA 0xB1                      ; 更新控制 2
CMD 0x20                                 ; 主激活
wait_busy()
```

## 4. 图像格式与刷新（`0x0100FF04` 平面写入器）

一次传 **30000 字节**，两半：

* `[0 .. 14999]`  −→ `CMD 0x24`（黑白平面），400x300、每行 50 字节、行优先
* `[15000 .. 29999]` −→ `CMD 0x26`（红色平面），同样排布

写入前会先发 `CMD 0x4E 0x00 0x00` + `CMD 0x4F (rows-1)&0xFF, (rows-1)>>8`
设好游标，再发 `0x24` / `0x26`。

刷新（`0x0100FE20`）：

```
pins_init()
CMD 0x22, DATA 0xC7
CMD 0x20
wait_busy()
pins_release()       ; 0x1010DC0 把 7 根脚都设成 mode3/arg0
```
