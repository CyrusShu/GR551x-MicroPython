## 解读

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 芯片 | `hd_info: 5513` | 确认 GR5513，与丝印 GR5513BEND 一致 |
| Bootloader 加载地址 | `0x01003000` | 大小 `0x3b00`（15104 B），结束于 `0x01006B00` 附近 |
| 应用程序加载地址 | `0x0100A000` | 大小 `0x1f8f0`（129264 B），结束于 `0x010298F0` 附近 |
| NVDS | `0x0107F000` | 最后一个 4KB 扇区 |
| 固件版本 | `version: 2.2.36` | ZKONG 应用版本 |
| 型号 | `ZKC42V-N <67 3>` | 4.2 寸 |
| BLE MAC | `a0:a3:b8:2d:96:ea` | **设备唯一，务必记录** |
| secret | `0xf2 0x84 0xc2 0x53` | 设备密钥 / ID |
| NFC | tag `0x12`，uid `1D EA F3 AD` | 板载 NFC |
| 电池电压 | 3308 mV | 与外部 3.3V 供电一致 |
| 状态 | `no AP, sleep 30000s` | 没找到基站，进入长睡眠 |

## 实际 flash 布局

```
0x01000000  +--------------------------+
            |  ROM boot 入口 / 保留      |  12 KB
0x01003000  +--------------------------+
            |  原厂 Bootloader (DFU)     |  ~15 KB
0x01006B00  +--------------------------+
            |  (空洞)                   |
0x0100A000  +--------------------------+
            |  原厂应用 2.2.36           |  ~126 KB
0x010298F0  +--------------------------+
            |  (空洞)                   |
0x0107F000  +--------------------------+
            |  NVDS                     |  4 KB
0x01080000  +--------------------------+
```

## 两个重要结论

1. **MCU 活着，原厂固件完整在跑。** 供电问题和"芯片没通电"的怀疑全部排除。
2. **这块 tag 不用官方 SDK 的默认布局。** SDK 默认 app 在 `0x01002000`，
   而这个 tag 的 bootloader 在 `0x01003000`、应用在 `0x0100A000`。
   以后要把自编固件烧进去时，**必须先弄清 ROM 是按什么找 bootloader 的**
   （很可能是 OTP/eFuse 里的 `bl0_boot_info`，而不是 flash 里的固定位置），
   否则直接把镜像烧到 `0x01002000` 可能根本不会被引导。

## 对 SWD 连不上的解释

日志最后一行是 `no AP, sleep 30000s` —— 应用找不到基站，要进入长睡眠。
这类电池价签为了省电，通常在启动后调用 `sys_swd_disable()`（SDK 里确有这个 API），
并关掉调试相关电源。于是：

- **复位后的 ROM / bootloader 阶段，SWD 还是活的**（日志证明这两段确实跑了）；
- **应用一接管就没了。**

所以必须用 **connect-under-reset**：在复位瞬间抓住 SWD，趁应用还没关掉它的时候把 CPU halt 住。

## 备份清单

完整备份要覆盖 `0x01000000 ~ 0x01080000` 整片 512KB，重点区段：

| 区段 | 内容 |
| --- | --- |
| `0x01000000` + `0x3000` | ROM boot 入口区 |
| `0x01003000` + `0x3b00` | 原厂 Bootloader |
| `0x0100A000` + `0x1f8f0` | 原厂应用 2.2.36 |
| `0x0107F000` + `0x1000` | NVDS |
